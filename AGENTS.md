## UI and frontend design requirements

Read `DESIGN.md` before implementing or modifying any user-facing interface.

Treat its principles as project requirements, not optional aesthetic suggestions.

Before implementing a substantial UI change, determine the page's hierarchy, layout grid, reusable components, and design tokens.

After implementation, review the rendered interface when tooling allows. Check alignment, spacing, typography, visual hierarchy, consistency, and responsiveness. Fix visual inconsistencies rather than merely confirming the code compiles.

When design requirements are ambiguous, prefer the simpler, more cohesive solution. Do not invent decorative elements to fill space.

Do not introduce visual patterns inconsistent with the existing application or `DESIGN.md`.
